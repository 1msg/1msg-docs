title: Channel ID + JWT
description: Где взять ID канала и JWT-токен, как передать их в запросе к API и что значат ошибки авторизации.
---

В каждом запросе к API нужны два значения. **Channel ID** показывает, с какого номера отправлять, а **JWT-токен** подтверждает, что запрос ваш. Оба есть на странице канала.

Ниже: где их найти, как добавить в запрос, как проверить и что делать при ошибке.

## Шаг 1. Откройте страницу канала

Войдите в [**platform.1msg.io**](https://platform.1msg.io/) и откройте канал, с которого будете отправлять. Если подключено несколько номеров, каждый из них — отдельный канал со своим токеном.

Если аккаунта ещё нет, начните с [Быстрого старта](../platform/quickstart.ru.md): там можно активировать тестовый канал и отправить первое сообщение, не дожидаясь одобрения Meta.

## Шаг 2. Скопируйте Channel ID и токен

На странице канала есть:

* **Channel ID** — короткий ID, его подставляют в URL запроса;
* **JWT Token** — строка, которую нужно передавать в каждом запросе.

Токен — это пароль: с ним кто угодно сможет отправлять сообщения от имени бизнеса. Храните его в переменных окружения на сервере. Не вставляйте его во фронтенд, не кладите в публичный репозиторий и не показывайте на скриншотах.

## Шаг 3. Добавьте их в запрос

Запросы идут на [**api.1msg.io**](https://api.1msg.io/). Channel ID стоит в URL сразу после хоста:

```
https://api.1msg.io/{channelId}/sendMessage
```

Токен можно передать двумя способами. Они равнозначны: API ищет токен сначала в теле запроса, потом в строке запроса, потом в заголовке.

**В заголовке — рекомендуем:**

```bash
curl -X POST "https://api.1msg.io/{channelId}/sendMessage" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"phone": "79001234567", "body": "Hello 1msg"}'
```

Токен из заголовка не попадает в логи доступа сервера и в историю браузера, поэтому в продакшене лучше передавать его так.

**В строке запроса:**

```bash
curl -X POST "https://api.1msg.io/{channelId}/sendMessage?token={token}" \
  -H "Content-Type: application/json" \
  -d '{"phone": "79001234567", "body": "Hello 1msg"}'
```

Удобно для быстрой проверки, но токен окажется в логах доступа и на прокси. В продакшене так не делайте.

## Шаг 4. Проверьте, что всё работает

Откройте [Playground](https://platform.1msg.io/dashboard/playground) в дашборде. Он сам подставит Channel ID и токен и покажет готовый JSON запроса, ответ API и то, что пришло на вебхук. Если сообщение доставлено, значит, Channel ID и токен верные, а этот JSON можно перенести в свой код.

## Если запрос не прошёл

**`token is required`, код 401.** Токен не дошёл до API. Проверьте, что он есть хотя бы в одном месте: в теле запроса или в заголовке.

**`access denied`, код 403.** Самая частая ошибка. Причины две: токен неверный (опечатка, обрезался при копировании) или он от другого канала, а не от того, что в URL. Скопируйте ID и токен заново с одной и той же страницы канала.

**`Invalid API KEY`, код 401.** Токен дошёл до WhatsApp, но там его отклонили. Обычно это значит, что канал больше не подключён. Проверьте его статус в дашборде.

**`Instance not found`, код 404.** В URL неверный Channel ID. Проверьте, что он скопирован целиком и без пробелов.

## Один канал — один токен

У каждого канала свой токен. Если у бизнеса несколько номеров WhatsApp, то и каналов несколько, и токенов. Токен одного канала не подойдёт для отправки с другого.
